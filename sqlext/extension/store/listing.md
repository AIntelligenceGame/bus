## 1. 基本信息

| 后台字段 | 限制 | 建议填写 |
|---|---|---|
| **扩展名称**（Name） | 45 字符 | `SQL 结构化解析` |
| **简短说明**（Summary） | 132 字符 | `把网页里的 SQL 解析成结构化 JSON：表、字段、条件、索引、CTE。解析在服务器端完成。` |
| **类别**（Category） | 单选 | `开发者工具`（Developer Tools） |
| **语言**（Language） | 单选 | `中文（简体）` |

### 名称为什么这么写

商店搜索靠**名称 + 简短说明 + 关键词**的匹配。用户会搜的词是：

- `SQL 解析`、`SQL 分析`、`慢查询`、`慢日志`、`SQL 格式化`、`SQL 解释`
- `MySQL`、`SQL 工具`、`SQL helper`

所以名称直接放「SQL」+「解析」，简短说明放「结构化 JSON / 表 / 字段 / 索引 / 慢查询」。

**不要**把名字起成「XX 助手」「XX 平台」这种跟 SQL 无关的词——搜不到。

## 2. 详细说明（Detailed description，16000 字符）

```markdown
把网页里的 SQL 变成你能直接用的结构化数据。

## 它解决什么问题

运维/DBA 拿到一堆慢日志里的 SQL，需要人工拆解：涉及哪些表？哪些字段？
怎么关联？有没有走索引？一条十几个 JOIN 的查询，光看源码很难理清。

本扩展把 SQL 解析成结构化 JSON，**表名、字段名、WHERE 条件、JOIN 关系、
子查询、CTE、索引提示**全部拆出来，直接喂给你的工具。

## 怎么用

**一、授权你想用的网站**

点插件图标 → 「授权当前网站」。只有你授权过的网站才能调用解析服务。
未授权的网站里 `window.sqlext` 根本不存在——你的额度不会被陌生网站偷偷烧掉。

**二、在网页里调用**

```js
const r = await window.sqlext.parse('SELECT id, name FROM users WHERE status = 1');

r.statement.details.from;            // "users"
r.statement.details.selected_exprs;  // ["id", "name"]
r.statement.details.where;           // 条件结构
r.balance;                            // 剩余额度
```

**三、或者直接用网页版**

不想装插件的话，同一个解析服务也提供网页版，粘贴 SQL 即可。

## 特点

- **解析在服务器端**：解析能力随时更新，不用等扩展发版
- **按站点授权**：三重校验（内容脚本注册范围 + 后台校验 + 服务端校验），
  任意网站无法消耗你的额度
- **令牌不出扩展**：登录凭证只存在扩展的本地存储里，网页脚本永远拿不到
- **额度透明**：每次解析扣多少、还剩多少，插件里随时能看到

## 支持的 SQL

MySQL 语法（基于 go-mysql-server / vitess 解析器）：
`SELECT` / `INSERT` / `UPDATE` / `DELETE` / `REPLACE` / `CREATE TABLE` /
`ALTER TABLE` / `DROP` / `SHOW` / `EXPLAIN` / `SET` 等，
支持 JOIN、子查询、CTE、窗口函数、注释（含 `/*! ... */` MySQL 特有注释）。

## 费用

新用户赠送免费额度，用完可以充值。解析在服务器端运行，按次计费。

## 隐私

- 你提交的 SQL 会发送到我们的服务器进行解析
- 登录邮箱、余额、订单记录保存在我们的服务器上
- 不会读取或上传你在其他网站上的任何浏览数据
- 不收集广告标识符，不做用户画像

完整说明见隐私政策。

## 3. 权限说明（商店必填，必须逐条解释）

后台会问每个权限「为什么需要」，填这些：

| 权限 | 后台填的理由 |
|---|---|
| `storage` | 保存登录令牌、服务器地址、已授权站点列表。不存储任何浏览数据。 |
| `scripting` | 在**你已授权的网站**上注入解析接口（`window.sqlext`），这是扩展的核心功能。未授权的网站不会被注入。 |
| `activeTab` | 用户点击插件图标时，读取当前标签页的网址以确定要授权哪个网站。 |
| 可选主机权限 `http://*/*` `https://*/*` | 用户授权某个网站时，按需申请该站点的主机权限，用于注入解析接口。**不申请全站权限**，只在用户逐个授权后生效。 |

### 隐私实践问卷

后台「隐私实践」部分要如实申报：

- **收集哪些数据**：用户提交的 SQL 语句、账号邮箱、充值订单
- **收集目的**：提供解析服务、处理支付
- **数据是否出售**：否
- **数据是否用于广告**：否
- **数据加密传输**：是（HTTPS）
- **用户能否要求删除数据**：是（联系邮箱即可）

> ⚠️ **不要漏填**。商店审核会核对问卷与实际行为，填错或漏填直接被拒。

## 5. 审核会被问什么

提前准备答案（写在文档里，审核员可能让你补充说明）：

**Q：为什么解析逻辑不在扩展里？**
> 解析器依赖 `go-mysql-server` / `vitess`（WASM 化不现实，且体积巨大）。
> 放在服务端还有个好处：解析能力升级不需要用户重新安装扩展。
> 扩展只负责转发和账号管理，符合 Chrome MV3 关于「与远程服务器通信」的允许场景
> （服务端返回的是 JSON 数据，不是可执行代码）。

**Q：任意网站能不能调用这个付费接口？**
> 不能。三层防护：① 内容脚本只注册在用户逐个授权过的站点上；
> ② 后台再校验一次授权列表；③ 服务端按请求来源 origin 再校验一次。
> 扩展被篡改也绕不过服务端这层。

**Q：这个扩展有没有单一用途？**
> 有——把 SQL 解析成结构化数据。注册/登录/充值页都是为这个用途服务的账号体系。

## 6. 上架后

- **版本更新**：改 `manifest.json` 的 `version`，跑 `package.sh` 重新打包上传
- **自动更新**：商店自己管，用户不用手动更新
- **看数据**：开发者后台有安装量、评分、错误报告

## 7. 审核不通过的退路

如果公开商店过不了审（尤其是「纯转发薄壳」被质疑）：

1. **自建分发**：CRX 自签名 + 企业策略推送，给内部团队/企业客户
2. **Edge 加载项**：Microsoft Edge 审核相对宽松，同时能覆盖 Edge 用户
3. **Firefox**：Firefox 商店审核更温和（MV3 已支持），但要单独写 manifest
4. **网页版**：不依赖商店，SEO 导流（这也是市场调研的主要结论）
